Tahaif Infrastructure Review تحائف

What it takes to run the Tahaif gift-delivery platform outside a laptop: every service the code actually calls, the problems that would stop a deploy today, a zero-cost stack for a shared development server, and production options that bill by usage instead of by reserved capacity.

Web Next.js 15 · React 19 API FastAPI · Python 3.12 · SQLAlchemy async Data Postgres 16 · Redis 7 · Meilisearch · S3 Money BIGINT paisa, PKR base, 7 FX quotes

Summary

The application needs 5 self-hosted runtime pieces (web, API, worker/scheduler, Postgres, Redis), 2 stateful add-ons (Meilisearch, object storage) and up to 8 SaaS APIs. All of it fits in free tiers for a dev server. Production can start at roughly $25–45/month and grow with traffic.

Blocks deploy today6 issues

Both Dockerfiles fail to build or boot, the Fly health check hits a path that does not exist, and no background worker runs.

Dev server$0 / mo

Vercel Hobby + Render/Koyeb free API + Neon + Upstash + R2 + Resend. Or one Oracle Always Free VM running the existing compose file.

Production, launch≈ $25–45

Cloud Run + Neon Launch + Upstash PAYG + R2 + Meilisearch on a small VM, with web on Vercel Pro. Scales to zero between orders.

Recommendation. Use the serverless, usage-billed stack (Option B below) for production and the free-tier version of the same stack for the dev server, so dev and prod differ only in plan size. Fix the six blockers first; none of the hosting choices work until the images build.

Deploy blockers and risks

Checked against the code at f3633b2. The API image was reproduced locally: its dependency install succeeds, then import app.main from /app fails with ModuleNotFoundError: No module named 'app'.

blocker

API container cannot start

The image sets WORKDIR /app but copies the package to /app/apps/api/app, and the CMD runs uvicorn app.main:app from /app.

infra/Dockerfile.api:2, :15, :21

Fix: add WORKDIR /app/apps/api in the runtime stage (also makes alembic.ini resolvable), and use uv sync --no-install-project in the builder.

blocker

Migration release command uses a binary that isn't in the image

uv is installed only in the builder stage. The runtime venv has alembic but no uv, so every Fly deploy fails at the release step.

infra/fly.toml:46

Fix: release_command = "alembic upgrade head" (the venv is already on PATH).

blocker

Health check targets a route that returns 404

Fly probes /health; the API serves /api/v1/healthz and /api/v1/readyz. Machines never pass the check. readyz also doesn't test DB or Redis yet.

infra/fly.toml:34 · apps/api/app/api/v1/endpoints/health.py

Fix: point the check at /api/v1/healthz; add DB SELECT 1 and Redis PING to readyz.

blocker

Web image fails at install and copy steps

pnpm install --frozen-lockfile runs with only package.json; the lockfile lives at the repo root. The runner stage copies /app/public, which doesn't exist. With outputFileTracingRoot set to the monorepo root, server.js lands at .next/standalone/apps/web/server.js, not the root.

infra/Dockerfile.web:7–8, :26, :35 · apps/web/next.config.ts

Fix: only matters if you self-host the web app. On Vercel this file is unused. Otherwise copy pnpm-lock.yaml + pnpm-workspace.yaml, create public/, and run node apps/web/server.js.

blocker

No worker process exists

Order confirmations are written to notifications_outbox, but nothing drains it. The runbook lists arq schedules that aren't defined anywhere, so customers get no confirmation email or SMS.

apps/api/app/workers/outbox_worker.py · docs/runbook.md §8

Fix: add a small CLI entrypoint (python -m app.workers.run outbox|fx) and trigger it on a schedule. The outbox already uses SKIP LOCKED, so a cron job works without a queue; arq can come later.

blocker

Auth breaks across different domains

Refresh cookies are SameSite=Lax and the web client uses credentials: "include". On default hostnames like *.vercel.app + *.onrender.com, the browser won't send the cookie. COOKIE_SECURE defaults to false.

apps/api/app/api/v1/endpoints/auth.py:73 · apps/api/app/core/config.py:40

Fix: use custom subdomains on every environment (dev.tahaif.pk + api.dev.tahaif.pk), and set COOKIE_SECURE=true outside local.

risk

Bank-transfer receipts are stored at public URLs

Proof uploads return a public object URL. These are financial documents with customer names and account details.

apps/api/app/integrations/s3_client.py:38–41

Fix: private bucket for proofs/, serve through short-lived presigned GET URLs to admins only. Keep product images in a separate public bucket.

risk

Connection pool too large for free and serverless Postgres

pool_size=10, max_overflow=20 per process, × 2 uvicorn workers, × every instance. Three instances can open 180 connections; free Postgres tiers allow far fewer.

apps/api/app/core/db.py:14–15

Fix: make pool size an env var (2–5 on serverless), connect through the provider's PgBouncer endpoint, and pass connect_args={"statement_cache_size": 0} for asyncpg in transaction-pooling mode.

risk

Rate limits are per process, not global

The slowapi Limiter has no storage_uri, so the 200/min limit is counted in memory and multiplies with each worker and instance.

apps/api/app/core/rate_limit.py:8

Fix: Limiter(..., storage_uri=settings.redis_url).

risk

Content-Security-Policy will block PostHog and media

connect-src doesn't include the PostHog host, and img-src allows only *.tahaif.pk and Unsplash, so images from an R2/S3 domain won't render.

apps/web/next.config.ts:16–17

Fix: add NEXT_PUBLIC_POSTHOG_HOST to connect-src, and the media domain to img-src and images.remotePatterns.

cleanup

Config drift between files

fly.toml says region sin, the runbook says iad. The README says tahaif.pk, env and runbook say tahaif.com. fly.toml asks for ALLOWED_ORIGINS but the code reads FRONTEND_URL. .env.example lacks FRONTEND_URL, COOKIE_SECURE, GOOGLE_*. NEXT_PUBLIC_MEILISEARCH_* are unused. Compose pins :latest for Meilisearch, MinIO and MailHog. The empty [[statics]] and [mounts] tables in fly.toml should be removed.

infra/fly.toml · docs/runbook.md · .env.example · infra/docker-compose.yml

Free dev server

Two ways to get a shared, always-reachable dev environment for $0. Both need a domain you control so cookies work (see blocker 6). A .pk domain from PKNIC or any cheap .com costs money; subdomains of it are free.

Recommended · mirrors production

A. Free tiers of the production stack

  • Web: Vercel Hobby, preview deploys per PR
  • API: Render free web service or Koyeb free instance (Docker). Cloud Run's free tier also fits and is the same product as prod
  • Worker: GitHub Actions cron calling a protected POST /internal/jobs/outbox every 15 min
  • Postgres: Neon free (0.5 GB, scales to zero, DB branch per PR)
  • Redis: Upstash free (256 MB)
  • Storage: Cloudflare R2 free (10 GB, no egress fees)
  • Search: leave Meilisearch unset, or run it on the Oracle VM from option B
  • Email: Resend free (3,000/mo, 100/day). Twilio trial credit only
  • Errors: Sentry Developer, PostHog free
Good
  • Same config shape as prod
  • PR previews for web and DB
  • No servers to patch
Watch
  • Render free sleeps after 15 min idle, ~30–60 s cold start
  • Neon compute suspends when idle, first query is slower
  • Vercel Hobby is for non-commercial use only; fine for dev, not prod
Closest to local compose

B. One Oracle Always Free VM

  • Machine: Ampere A1, up to 4 OCPU and 24 GB RAM, 200 GB block storage, always free
  • Region: Dubai, Abu Dhabi or Jeddah for Pakistan latency
  • Runs: the existing docker-compose.yml (Postgres, Redis, Meilisearch, MinIO, MailHog) plus API and web containers
  • Edge: Caddy for automatic TLS, or a Cloudflare Tunnel so no port is open
  • Worker: host crontab running docker compose exec api python -m app.workers.run outbox
Good
  • Everything in one place, including Meilisearch and MailHog
  • No sleep or cold starts
  • Plenty of headroom for load tests with infra/load-test.js
Watch
  • ARM64: images must be multi-arch (all current ones are)
  • Signup needs a card; A1 capacity can be scarce in some regions
  • Idle free instances can be reclaimed; you own backups and OS patching
Other free options considered. Fly.io no longer has a free allowance for new organizations (small Machines cost about $2–6/mo each). Supabase free pauses after a week without activity and its 500 MB DB is fine, but Neon's branching suits PR previews better. Railway gives a one-time trial credit, then $5/mo. GCP's always-free e2-micro (1 GB) is US-only and too small for Meilisearch.

Why B for Tahaif

Gift delivery is spiky. Orders cluster around a handful of dates, and between them the API is mostly idle. Cloud Run and Neon both drop to near zero during quiet weeks and scale out on Eid morning without a capacity decision. R2's zero egress matters because product photos are the heaviest thing the site serves. The one fixed cost is Meilisearch, which needs a disk; a $5 VM covers the catalog for a long time.

Keep min instances = 1 on the API from launch onward. A cold Python container with SQLAlchemy and boto3 takes a few seconds to start, which is too slow for checkout. That adds roughly $10–15/mo on Cloud Run, and is included in the estimates below.

Region and latency

Two audiences pull in different directions: buyers in Pakistan and the diaspora in the UK, US, Canada, Australia and the Gulf.

Put state near Pakistan

No major cloud has a Pakistan region. Traffic from PTCL, Jazz and Zong usually exits through the Gulf, Singapore or Europe, so test each candidate from Pakistani ISPs before choosing. Good candidates: me-central1 (Doha) or asia-south1 (Mumbai) on GCP, Singapore on Neon and Fly (the current fly.toml already says sin). Keep the API, Postgres, Redis and Meilisearch in the same region; each checkout makes many DB round-trips.

Serve pages from the edge

Diaspora users mostly browse, and catalog pages are cacheable. Vercel or Cloudflare serve static assets and ISR pages from nearby edges, so a UK visitor only pays the long hop on cart and checkout calls. Product images on R2 behind a Cloudflare custom domain are cached globally.

Rollout plan

In order. Each step can be verified before the next.

  1. Fix the container builds. Runtime WORKDIR, --no-install-project, drop uv from the release command, correct health path. Add a CI job that runs docker build for the API on every PR so this can't regress.Done when: docker run answers /api/v1/healthz.
  2. Add the job entrypoint. python -m app.workers.run outbox|fx, plus a token-protected internal endpoint for environments without a job runner.Done when: placing a test order produces an email in Resend's log within one schedule tick.
  3. Make config environment-safe. Pool size from env, statement_cache_size=0, Redis-backed rate limits, readyz checks DB and Redis, CSP additions, private proofs bucket with presigned URLs. Update .env.example.
  4. Register the domain and DNS on Cloudflare. Create dev., api.dev., media.dev. records. Pick one of tahaif.pk / tahaif.com and update README, runbook and CSP to match.
  5. Stand up the dev server (Option A). Neon, Upstash, R2, Resend accounts; API on Cloud Run or Render; web on Vercel Hobby. Run alembic upgrade head and scripts/seed.py once.Done when: the five Playwright specs in apps/web/tests pass against the dev URL.
  6. Add a deploy workflow. On merge to main: build, push to Artifact Registry/GHCR, migrate, deploy to dev. Production deploys on a tagged release with a manual approval.
  7. Load-test before launch. Run infra/load-test.js against dev with production-sized DB settings to pick Cloud Run concurrency and max instances, and confirm p95 under 500 ms.
  8. Promote to production (Option B). Upgrade Vercel to Pro, Neon to Launch, set API min instances to 1, deploy Meilisearch VM with a volume and snapshot backups, enable Neon PITR, rewrite the runbook for the chosen platform.
